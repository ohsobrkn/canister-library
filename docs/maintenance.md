# 暗盒图片库 · 日常维护手册

面向维护者（ohsobrkn）的自助维护说明。所有操作都在浏览器完成，无需接触代码或命令行。

## 1. 准备：创建 PAT（首次 / 每 90 天一次）

1. 打开 GitHub → 右上头像 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. 配置：
   - **Repository access** → Only select repositories → 选 `ohsobrkn/canister-library`
   - **Permissions → Repository permissions → Contents → Read and write**（其余权限一律不动）
   - **Expiration** → 90 天
3. 生成后复制 `github_pat_…` 令牌
4. 打开 `https://ohsobrkn.github.io/canister-library/admin.html`，填写仓库（默认值已预填）、粘贴 PAT → **保存并连接**

令牌只保存在你本浏览器的 localStorage，不写入任何文件。到期前 GitHub 会发邮件提醒，重复上述步骤换新令牌粘贴即可（旧令牌可在 GitHub 上吊销）。

## 2. 批量上传

管理端 →「批量上传」页签：

1. （可选）先在「新图默认值」里填好厂商 / 类型 / ISO 并点「应用为默认」，之后入队的每张图自动带上
2. 把图片拖进虚线框（可多选），每张自动生成缩略图，队列中可逐张补填元数据
3. 点「提交上传」→ 全部图片 + 元数据打包成**一次提交** → 等待 Pages 构建（约 1–3 分钟），界面提示「已生效」后公开页可见

原图按你选择的策略**无损保存**（不压缩）。注意页面顶部的「仓库体积」卡片：超过 800MB 会提醒、接近 950MB 变红——届时按第 6 节把原图迁移到 Release 附件。

## 3. 修改 / 重新归类 / 删除

「图库管理」页签：

- **单张编辑**：点「编辑」展开表单（厂商输入框带自动补全，可直接输入字典里没有的新厂商），「应用修改」后点顶部「保存并提交」
- **批量套用**：勾选多张 → 可设为隐藏 / 公开；逐张字段批量套用可用「新图默认值」+ 单张编辑组合，或直接多选后删除重传
- **删除**：单张「删除」或勾选后「删除所选」，保存时连同图片文件一起从仓库移除（Git 历史中仍留有旧文件记录）
- **隐藏**：临时下架不删档，公开页不再显示，随时可恢复
- **查找未补全**：勾选「只看未补全元数据」可快速定位需要补信息的条目

所有修改在「保存并提交」之前都只是本地暂存（顶部黄色横条会提示未保存数量），提交后同样等待 Pages 构建生效。

## 4. 自定义分类维度

「字典与维度」页签：

- **厂商字典**：直接增删值。新增值保存后，公开页筛选器与表单自动补全同步出现
- **新增维度**：填英文标识（如 `format`）、显示名（如 `画幅`）、类型、初始值。保存后前后台自动出现该筛选维度
- **移除维度**：从界面移除，条目里已填的数据保留在 JSON 中不丢失

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 提交后公开页没变化 | Pages 构建约需 1–3 分钟，管理端会轮询并提示「已生效」；也可强制刷新（Ctrl+F5） |
| 「PAT 无效或已过期」 | 令牌到期或权限不足，按第 1 节重新生成 |
| 上传单张失败提示 >95MB | GitHub 单文件上限 100MB，需先压缩或拆分 |
| 「API 限流」 | 每小时 5000 次，批量上传几十张通常用不到 1%，等一小时即可 |

## 6. 仓库体积治理（重要）

原图无损保存意味着仓库体积随张数线性增长（2–4MB/张，约 300–500 张触及 GitHub 1GB 软上限）。管理端首页有体积卡片，超 800MB 会主动提醒。治理方案（届时执行）：

1. 在 GitHub 网页为该仓库创建一个 Release（如 `originals-archive-v1`），把全部原图作为附件上传（单文件上限 2GB，不计仓库体积）
2. 用管理端逐批重新上传压缩版原图（或让维护助手处理），仓库内保留压缩版 + 缩略图 + 元数据
3. 公开页加载链路不变（列表用缩略图，大图用仓库内图片）

如需彻底瘦身（重写 Git 历史移除旧大文件），属于一次性维护操作，可交给 AI 助手执行。

## 7. 安全边界（知悉即可）

- 纯静态方案没有服务端，PAT 存于浏览器前端：**泄露影响面 = 仅本仓库的图片与 JSON 可被改写**，碰不到你的其他仓库与账号（fine-grained 最小权限的作用）
- admin 页仅在 GitHub Pages 的 https 域下使用；不要把 PAT 粘贴到任何其他页面或聊天工具
- 换电脑 / 换浏览器维护：重新生成一个 PAT 粘贴即可，无迁移成本
